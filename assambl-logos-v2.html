Cursor

La pieza naranja crece hasta la altura de la letra y se convierte en un cursor de bloque. Parpadea: el sistema está esperando tu próxima decisión.

Concepto

Mínimo cambio, máxima carga semántica. El bloque final del Monolith original ya parecía una pieza colocada; ahora es un block cursor de terminal. El logo queda “vivo” en la UI (parpadeo) y estático en impresión. El naranja pasa de acento decorativo a indicador de estado: naranja = esperando input, verde = resolved.

Statement

El nombre termina en punto y coma. Una sentencia completa, ejecutable. Nada más que agregar.

Concepto

El ; es el signo más reconocible de la sintaxis de programación y a la vez el más silencioso: un no-programador lo lee como puntuación enfática. El tagline se construye con la misma lógica: design; resolve; build; — tres sentencias, un programa. El azul eléctrico reemplaza al naranja para alejarse del look “startup 2023” y acercarse al azul de sintaxis de los editores.

Comment

Doble barra delante del nombre: el prefijo de comentario. Lo que sigue es una nota humana dentro del código.

Concepto

Un comentario es la parte del código escrita para personas, no para la máquina. Es exactamente el lugar del usuario en Assambl: escribe intención en lenguaje natural; el compilador hace el resto. El // además evoca dos studs paralelos o dos líneas de cota. Funciona solo como ícono y como prefijo de todo el sistema de microcopy (// wall moved. structure updated.).

Call

El nombre como llamada a función. Assambl no es una cosa: es una acción que recibe una intención y devuelve un edificio.

Concepto

Los paréntesis convierten el sustantivo en verbo. La firma de función es el pitch entero en una línea: assambl(intent) → building. Permite jugar con el argumento en cada contexto: ASSAMBL(house), ASSAMBL(cabin), ASSAMBL(your idea). Los paréntesis además dibujan dos arcos que “abrazan” y cierran, como un ensamble.

Prompt

El signo de prompt de la terminal delante del nombre. Assambl es un comando que se invoca; el ámbar es fósforo de monitor antiguo.

Concepto

Reemplaza el _ del original por el $: donde el cursor decía “esperando”, el prompt dice “listo para recibir órdenes”. El ámbar (#FFB000) es el color del fósforo P3 de los monitores de los 80: cálido, técnico y muy distinto del verde Vercel/Supabase. El prompt además abre un lenguaje natural para la UI: el usuario literalmente escribe $ assambl "cabaña A-frame, 2 dormitorios".

Method

Notación de punto: assambl.build(). El nombre es el objeto; lo que hace son sus métodos. La versión corta es solo el nombre con un punto verde.

Concepto

Cada capacidad del producto se vuelve un método legible: assambl.build(), assambl.resolve(), assambl.quote(), assambl.export(bim). El naming de features sale gratis y siempre suena a sistema. Para uso general se usa la forma corta assambl.: el punto verde es la promesa de que algo sigue. El punto solo, sobre la “a”, es un ícono limpio y muy escalable.

Diff

El logo como un diff de Git: se elimina una línea en rojo, se agrega Assambl en verde. La marca es el cambio que introduce.

Concepto

Todo programador reconoce la vista de diff al instante: rojo tachado arriba, verde con + abajo. Trasladado al producto: - drawings / + assambl, - 3 weeks / + 0.8 s. Es un formato de comunicación, no solo un logo: cada beneficio se puede expresar como un diff. La forma reducida + assambl es el logotipo del día a día; el + verde es el ícono.

Object

Llaves en lugar de corchetes: {assambl}. Ya no una lista sino un objeto con propiedades. La casa como estructura de datos con nombre.

Concepto

El cambio de [ ] a { } es pequeño pero conceptualmente exacto: un edificio en BIM es un objeto con propiedades (muros, studs, ventanas, errores: 0), no un array. Las llaves además tienen más “cuerpo” y remiten a las abrazaderas metálicas de una estructura. El objeto expandido es el tagline: el resultado del compilador escrito en JSON.

Key

El nombre como clave de un archivo de configuración: assambl: con dos puntos, y debajo, indentado, todo lo que resuelve.

Concepto

YAML es el formato de los archivos de configuración: legible por humanos, jerárquico, sin ruido. assambl: es la clave raíz; lo indentado son las capas del edificio con su estado. Es la variación más silenciosa de la familia: los dos puntos son casi invisibles pero cambian el registro a “declarativo”. Vos declarás qué querés; el sistema lo cumple. Se invierte la paleta: papel claro como fondo, azul como tinta, rojo de lapicera para los dos puntos.

Dimension

Sin corchetes. La palabra en mono, acotada como un elemento de plano: línea de cota, extremos y valor. Código y dibujo técnico en el mismo gesto.

Concepto

Es el puente más literal entre las dos culturas del producto. La fuente monoespaciada dice “código”; la línea de cota dice “plano”. La mono es, además, la única tipografía donde acotar tiene sentido: cada carácter mide exactamente lo mismo, como una grilla modular. El valor de la cota puede variar en cada aplicación: 7 chars, 2440 mm, 16" o.c., 0 errors.

Tag

Etiqueta autocerrada: <assambl/>. Un componente que se coloca y funciona. Papel claro, azul más vivo: la versión “diurna” de la familia.

Concepto

El markup es la sintaxis que más gente reconoce fuera de la programación (HTML). Una etiqueta autocerrada es un componente completo: lo insertás y ya está resuelto. Además, BIM se serializa en IFC/XML; la casa realmente es un árbol de tags anidados: <wall><stud/></wall>. Los < > dibujan dos flechas que apuntan hacia adentro: convergencia, ensamble.

Finalistas sugeridosA3 Comment (// ASSAMBL) y A2 Statement (ASSAMBL;) mantienen intacta la brutalidad del Monolith y suman código con un signo que también se lee como puntuación o como dos studs. B2 Method en su forma corta (assambl.) es la opción más elegante si querés un logo casi invisible con un sistema de naming enorme detrás.
Un híbrido que vale probarLas tres familias se pueden combinar: logotipo en Archivo Black (familia A) para la marca, e IBM Plex Mono (familia B) para toda la voz del producto: taglines en sintaxis, estados, microcopy. El “signo de código” del logo (; o //) se repite como prefijo en la UI. Así el código no está solo en el logo sino en cómo habla el producto.
Qué chequear antes de decidir1) Los signos ; // () a 16 px en la pestaña del navegador. 2) Que el signo elegido no dependa del color para leerse (probar en blanco y negro). 3) Búsqueda de marca: “//” y “;” no son registrables por sí mismos, pero sí en combinación con el nombre. 4) Pronunciación: ninguno de los signos se pronuncia, el nombre sigue siendo “Assambl”.
